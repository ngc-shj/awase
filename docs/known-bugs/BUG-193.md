# BUG-193: macOS で切替キーの KeyUp が KeyDown より先に注入される

**状態:** 修正済み（macOS）。上流 develop（v2.0.0）を macos-port へ取り込んだ時点で発生した退行。

**症状:** 左親指の 英数 を押したまま `simultaneous_threshold_ms`（100ms）が切れると、
OS へ届くイベントが「KeyUp(英数, 注入) → KeyDown(英数, 注入) → KeyUp(英数, 物理)」の
順になる。取り込み直後の実機ログ（2026-10-05、ATOK atok36）では、切替 10 回ほどのうち
2 回で ATOK が切替を受け付けず、300ms 後の張り直し（BUG-188）で回復していた。

```
35.236 phys 0x66 KeyDown LeftThumb -> consume
35.337 Engine deactivated
35.339 inj-tap 0x66 KeyUp
35.340 inj-tap 0x66 KeyDown
35.436 phys 0x66 KeyUp LeftThumb -> pass
35.660 WARN IME switch to open=false not observed within 300ms
```

**原因:** macOS の `run_effects` は、切替キー（英数/かな）の `SendKeys` を注入する
**前に** `expect_ime_from_key` で切替の期待を立て、その中で `RefreshState` を engine に
送っていた。上流の取り込みで、engine が非活性化するときの処理が
`release_pending_and_reinject` に変わり、押下中のキーの KeyUp を即座に出すように
なった（取り込み前は `flush_pending_key_ups()` の戻り値を捨てていた）。そのため、
期待を立てた瞬間の非活性化で 英数 の KeyUp が先に注入され、続いて本来の KeyDown が
注入されていた。

**修正:** `crates/awase-macos/src/main.rs` の `run_effects` で、`SendKeys` の切替キーと
`ReinjectKey` の KeyDown を**注入してから**期待を立てる順に入れ替えた。OS へ届く順は
「KeyDown(注入) → KeyUp(注入) → KeyUp(物理)」になる。最後の物理 KeyUp は対応する
KeyDown の無い余分な KeyUp だが、取り込み前から同じ形で素通ししていたものと同等で、
切替自体には影響しない。

**テスト:** CGEvent の注入順はアプリ層（`App`）の中で決まり、`Output` が実際に
`CGEventPost` するため単体テストの基盤が無い。実機ログの `inj-tap` の順序で確認する。

**関連:** BUG-188（猶予切れ時の張り直し）、BUG-189（親指が切替キーを兼ねる構成）。
